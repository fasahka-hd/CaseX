Основные потоки данных
  1. Пользователь взаимодействует с Frontend
  2. Запросы проходят через API Gateway к нужному сервису
  3. Сервисы читают / записывают данные в БД, Redis
  4. Задачи отправляются в очередь RabbitMQ
  5. Steam Service передаёт задачи ботам
  6. Боты взаимодействуют со Steam
  7. Результат возвращается пользователю
Текущая реализация против целевой схемы
КомпонентСейчас в проектеСтатус
FrontendВанильный JS + morphdom, серверный рендер строк. Вся функциональность на месте, но это не React/TS SPAчастично
API GatewayРоуты Express в одном процессе — единая точка входа есть, отдельного шлюза нетчастично
Auth ServiceSteam OpenID + сессии в SQLite с HMAC-подписью. JWT не используетсячастично
Upgrade ServiceПолностью: серверный RNG (crypto.randomInt), шансы, история, коэффициентыесть
Case ServiceПолностью: взвешенный дроп, цены, вкл/выкл, история открытийесть
Inventory ServiceПолностью: site_inventory со статусами active / sold / usedесть
Payment ServiceЕсть внутренний баланс и таблица transactions. Реальных платёжных шлюзов и выводов нетплан
Steam ServiceТолько профиль и цены скинов. Trade Offer и загрузка инвентаря Steam не реализованычастично
Кластер ботовВ админке есть «боты витрины» для ленты дропов — это не Steam-боты с трейдамиплан
Админ-панельВсе 8 разделов реализованы, роли admin / support, журнал действийготово
База данныхPostgreSQL 17 через lib/db.js. SQLite остаётся запасным драйвером (DB_DRIVER). Есть скрипт миграции данныхвнедрён
RedisRedis 8 через lib/cache.js: кеш каталога и статистики, rate limiting со счётчиками и TTL, автоматический откат в память при обрывевнедрён
RabbitMQlib/queue.js: асинхронные топики drop.broadcast, stats.refresh, audit.write, notify.user с ретраями. Брокер RabbitMQ можно подключить вместо встроенногоочередь есть
Cloudflare / Nginxdeploy/nginx.conf: upstream с балансировкой, SSL, limit_req, real_ip от Cloudflare, отдельная локация для SSE. Плюс Dockerfile, docker-compose.yml и кроссплатформенные npm-скриптыконфиг готов
